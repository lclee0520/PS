# H — 제트팩 (오답 분석 포함)

- **문제**: `(0,0)`에서 출발해 `x = 0..N-1` 각 위치에서 "고도를 0으로 리셋할지"를 고른 뒤 `(x+1, y+1)`로 이동한다. 고도가 `M`이 되면 반드시 리셋해야 한다. `i`번째 장애물은 `x = i-1`에서 `y ≥ H_i`여야 넘는다. 모든 장애물을 넘는 리셋 위치 집합의 개수를 `10^9+7`로 나눠 출력한다.
- **코드**: [solution.cpp](solution.cpp) (정답 풀이). 아래는 제출 전 풀이(이하 "기존 풀이")를 분석한 기록이다.

### 1. 문제를 어떻게 바꿔 생각해야 하는가

- 위치 `x`에서 마지막으로 리셋한 위치를 `s`라 하면 고도는 `x - s`다.
- 장애물 조건 `y_x ≥ H`는 "`x-H+1 .. x` 구간에 리셋이 없다"와 같다. (`x-H`에서 리셋한 것은 괜찮다.)
- 강제 리셋 조건은 "리셋 없이 `M` 칸 연속으로 가면 안 된다"이다.
- 그래서 문제는 **일부 위치는 리셋 금지, 나머지는 자유이되 리셋 없는 구간이 `M`을 넘지 않는 이진 문자열의 개수**를 세는 것이다.

### 2. 기존 풀이에서 맞았던 부분

1. **`temp > i`이면 0**: 위치 `i`에서 도달할 수 있는 최대 고도가 `i`이므로 맞는 가지치기다.
2. **장애물이 리셋 금지 구간을 만든다는 관찰**: `H`가 0보다 큰 위치의 앞쪽 `H`칸에 리셋이 있으면 안 된다는 점을 잡아냈다. 이 관찰이 풀이의 핵심이다. `v[j] ≥ k`로 앞쪽 값을 올리는 반복문이 이 전파에 해당하고, 리셋 금지 구간의 크기(`H`칸)도 맞다.
3. **자유 위치는 2배, 금지 위치는 그대로**라는 카운팅 구조: `v[i] == 0`이면 리셋 여부를 골라 `total *= 2`, 아니면 리셋 불가로 `q.push(0)`을 한다. 리셋 없는 구간의 길이 제한은 `a_i = 2·a_{i-1} − a_{i-1-M}` 꼴의 점화식이므로, 큐로 `M`칸 전의 값을 빼는 아이디어도 맞는 방향이다.
4. **마지막 장애물을 별도로 처리**한 것도 이유가 있다. 반복문이 `n-2`까지만 전파해서 마지막 원소는 따로 전파해야 한다.

### 3. 기존 풀이에서 틀린 부분 (직접 돌려서 확인)

기존 풀이를 완전탐색(`N ≤ 4`, 가능한 입력 전부)과 비교하니 25개 입력에서 답이 달랐다. 원인은 크게 세 가지다.

**(1) 같은 높이가 이어질 때 금지 구간이 빠진다**
- 전파를 `v[i] > v[i+1]`일 때만 했다. 다음 값이 더 크면 그 다음 값의 구간이 현재 구간을 덮는다고 봤기 때문이다.
- 다음 값이 **같을 때**는 덮이지 않는다. 구간이 한 칸씩 밀려서, 앞쪽 끝 한 칸이 빠진다.
- 예: `N=4, M=4, H=[0,0,2,2]`
  - 정답은 1이다. `x=2`에서 고도 2가 되려면 `x=1`도 리셋하면 안 되기 때문이다.
  - 기존 풀이는 2를 냈다. `x=1`이 자유 위치로 남았다.
- 고치려면 `v[i] > v[i+1]` 조건 없이 모든 `i`에서 구간을 표시하면 된다. 겹치는 계산이 많아 보이지만, "금지 구간의 끝 위치"를 하나 유지하면 O(N)으로 가능하다.

**(2) `H = M`이면 불가능한데 가능하다고 본다**
- 고도가 `M`이 되면 그 자리에서 리셋해야 하므로 위치 `x`에서 **리셋 안 한 고도는 최대 `M-1`**이다. 따라서 `H_i = M`인 장애물은 절대 못 넘는다.
- 기존 코드는 `temp > m`만 걸러서 `temp == m`을 통과시켰다.
- 예: `N=2, M=1, H=[0,1]` → 정답 0, 기존 풀이 1.
- 참고로 `temp >= n` 검사는 `temp ≤ i ≤ n-1`이라 항상 거짓이라 필요 없고, `temp > m`은 제한(`H_i ≤ M`) 때문에 항상 거짓이다.

**(3) 마지막 위치에서 큐가 차지 않았는데 뺀다**
- 마지막 원소가 0일 때 `total -= q.front()`를 조건 없이 했다. 반복문 안에서는 `q.size() > m`일 때만 뺐는데, 마지막에서만 이 조건이 사라졌다.
- 큐 길이가 `M` 이하이면 강제 리셋에 걸린 경우가 없으니 뺄 것이 없다. 예: `N=M` 이고 전부 0이면 `2^(N-1)`인데 하나 적게 나온다. (`N=4, M=4, H=[0,0,0,0]` → 정답 8, 기존 풀이 7)
- 이 오류는 `H=[0,1,0]`, `M=3` 같은 입력에서도 나온다.

**그 밖의 약점**
- `total -= q.front()` 뒤에 `+MOD` 없이 `total <= 0`이면 0을 출력했다. 뺀 값이 음수가 될 수 있고, 정답이 나머지 연산 결과로 정확히 0이 되는 경우도 0과 구분하지 못한다. 모듈러 문제는 항상 빼기 뒤에 `+MOD`를 붙여야 한다.
- 위치 0을 반복문에서 빼고 초기값을 `1`, 큐도 `push(1)`로 손으로 맞추는 방식이라 경계가 많았다. 위치마다 같은 규칙을 쓰는 형태가 더 안전하다.

### 4. 정답 풀이 (solution.cpp)

- **핵심**: 통째로 조건을 나누지 않고, "마지막으로 고도가 0이 된 위치 `s`"별로 방법의 수 `w`를 덱에 들고 간다.
- **각 위치 `x`에서**
  1. 리셋 직전 전체 방법 수를 `total = sum`으로 기억한다.
  2. `x - s ≥ M`인 상태를 앞에서 제거한다. (리셋을 강제해야 하므로 리셋 없이는 살아남지 못한다.)
  3. `x - s < H[x]`인 상태를 뒤에서 제거한다. (고도 부족으로 장애물을 못 넘는다.) 최근 `s`부터 없어지므로 뒤에서만 빼면 된다.
  4. `H[x] == 0`이고 `x > 0`이면 여기서 리셋하는 경우를 `(x, total)`로 추가한다.
- **정답**은 마지막에 남은 `sum`이다.
- **시간복잡도**: 각 상태가 덱에 한 번 들어가고 한 번 나가서 O(N)이다.
- **`x = 0`의 리셋**: 이미 고도 0이므로 리셋해도 같은 경우로 본다. 이걸 별개로 세면 예제 2번이 1이 아니라 2가 나온다.

### 5. 다음에 같은 유형에서 확인할 것

- 조건을 "어떤 위치가 금지/자유인가"로 바꾸는 접근은 좋았다. 이제 **구간 표시는 모든 원소에서 하고, 겹침은 자료구조로 처리한다**는 점만 기억하면 된다.
- 손으로 만든 경계 처리(`i=1`부터, 마지막 따로)가 오답의 주된 원인이었다. 작은 `N`으로 완전탐색과 비교하는 테스트를 만들면 이런 경계 오류를 빨리 찾을 수 있다.
