## 사칙연산

- 문제번호: 1843
- 난이도: Level 4
- 유형: DP (구간 DP)

### 문제
사칙연산에서 덧셈은 결합법칙이 성립하지만, 뺄셈은 결합법칙이 성립하지 않는다. 따라서 연산 순서(괄호 위치)에 따라 결과가 달라진다.

- `((1 - 5) - 3) = -7`
- `(1 - (5 - 3)) = -1`

숫자와 연산자(`+`, `-`)가 번갈아 들어 있는 문자열 배열 `arr`가 주어질 때, 서로 다른 연산 순서의 계산 결과 중 **최댓값**을 반환하라.

- `arr` 길이: 3 이상 201 이하, 홀수
- 숫자: 1 이상 1,000 이하 자연수
- 연산자: `+`, `-`만 존재

### 입출력 예
| arr | result |
|-----|--------|
| `["1", "-", "3", "+", "5", "-", "8"]` | 1 |
| `["5", "-", "3", "+", "1", "+", "2", "-", "4"]` | 3 |

예제 1의 최댓값: `1 - ((3 + 5) - 8) = 1`

### 접근

#### 1. 숫자와 연산자 분리
`arr`를 숫자 배열 `num`과 연산자 배열 `ops`로 나눈다. 연산자를 만나면 바로 다음 숫자까지 같이 넣는다.

```
num:  1     3     5     8
ops:     -     +     -
      ops[0] ops[1] ops[2]
```

`ops[k]`는 항상 `num[k]`와 `num[k+1]` 사이의 연산자다. (`ops`는 `num`보다 하나 짧음)

#### 2. 구간 DP (역삼각 피라미드)
- `mx[i][j]`: `num[i]` ~ `num[j]` 구간을 계산할 때 나올 수 있는 **최댓값**
- `mn[i][j]`: 같은 구간의 **최솟값**
- 맨 아래층: `mx[i][i] = mn[i][i] = num[i]`
- 정답: 꼭대기 칸 `mx[0][n-1]`

#### 3. 최댓값만으로는 부족한 이유
`A - B`를 최대로 만들려면 `A`는 최대, `B`는 **최소**여야 한다. 그래서 각 구간마다 최댓값과 최솟값을 **둘 다** 들고 있어야 한다.

#### 4. 점화식
구간 `[i, j]`를 **마지막으로 계산할 연산자 위치 `k`** (`i ≤ k < j`) 기준으로 왼쪽 `[i, k]`와 오른쪽 `[k+1, j]`로 나눈다. 가능한 모든 `k`를 시도한다.

왼쪽 최대/최소 `a, b`, 오른쪽 최대/최소 `c, d`로 만들 수 있는 조합 4개를 모두 계산하고, 그중 최댓값은 `mx[i][j]`에, 최솟값은 `mn[i][j]`에 갱신한다.

| `ops[k]` | 후보 |
|----------|------|
| `+` | `a+c`, `a+d`, `b+c`, `b+d` |
| `-` | `a-c`, `a-d`, `b-c`, `b-d` |

> 실제로 필요한 조합은 연산자당 두 개다 (`-`면 최대 = `a - d`, 최소 = `b - c`). 하지만 4개를 모두 비교해도 결과가 같고, 어느 조합이 최대인지 따질 필요가 없어서 실수가 줄어든다.

`max({...})` 안에 **현재 `mx[i][j]`도 같이** 넣어서, `k`가 바뀌어도 지금까지 찾은 값 중 가장 좋은 값이 유지되게 한다. 이를 위해 초기값은 `INT_MIN` / `INT_MAX`로 둔다.

#### 5. 채우는 순서
`mx[i][j]`를 계산하려면 `mx[i][k]` (같은 행, `j`보다 왼쪽)와 `mx[k+1][j]` (아래 행)가 먼저 채워져 있어야 한다.
→ `i`는 **뒤에서부터** (`n-1 → 0`), `j`는 `i`부터 앞으로 채운다.

### 검산 (예제 1)
`num = [1, 3, 5, 8]`, `ops = [-, +, -]`

| 구간 | 식 | 후보 | mx | mn |
|------|----|------|----|----|
| [0,1] | 1 - 3 | -2 | -2 | -2 |
| [1,2] | 3 + 5 | 8 | 8 | 8 |
| [2,3] | 5 - 8 | -3 | -3 | -3 |
| [0,2] | 1 - (3+5) / (1-3) + 5 | -7, 3 | 3 | -7 |
| [1,3] | 3 + (5-8) / (3+5) - 8 | 0, 0 | 0 | 0 |
| [0,3] | 1 - [1,3] / [0,1] + [2,3] / [0,2] - 8 | 1 / -5 / -5, -15 | **1** | -15 |

정답 `mx[0][3] = 1`.

### 풀면서 막혔던 부분
- **부호를 숫자에 붙이기**: 처음엔 `5 - 3 + 1`을 `[5, -3, +1]`처럼 바꿨는데, `5 - (3 + 1)`처럼 괄호가 생기면 `+1`의 부호가 뒤집히는 걸 표현할 수 없다. → 숫자와 연산자를 따로 저장.
- **양 끝에서만 쪼개기**: "맨 앞 숫자 + 나머지", "나머지 + 맨 끝 숫자"만 보면 `(5-3) - (1+2)`처럼 가운데에서 나뉘는 경우를 놓친다. → `k` 반복문으로 모든 분할 지점을 확인.
- **채우는 순서**: `i`를 0부터 돌리면 아래 행 `mx[i+1][j]`가 아직 `INT_MIN`인 상태로 쓰여서 overflow가 난다. → `i`를 역순으로.

### 시간복잡도
O(N³) — 구간 `[i, j]` O(N²)개 × 분할 지점 `k` O(N). 숫자 개수 N ≤ 101이라 약 10⁶번 연산.

값 범위: 절댓값이 최대 101 × 1,000 = 101,000이라 `int`로 충분하다.
