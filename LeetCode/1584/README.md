## Min Cost to Connect All Points

- 문제번호: LeetCode 1584
- 난이도: Medium
- 유형: 최소 신장 트리 (MST) / 프림

### 문제
2차원 평면 위 점들의 좌표 배열 `points`가 주어진다 (`points[i] = [xi, yi]`). 두 점 `[xi, yi]`, `[xj, yj]`를 연결하는 비용은 맨해튼 거리 `|xi - xj| + |yi - yj|`이다. 어떤 두 점 사이에도 경로가 **정확히 하나**만 있도록 모든 점을 연결할 때 드는 **최소 비용**을 반환하는 함수를 완성하라.

- 1 ≤ points 길이 ≤ 1000
- -10⁶ ≤ xi, yi ≤ 10⁶
- 모든 점의 좌표 쌍은 서로 다르다

### 입출력 예
| points | 결과 |
|--------|------|
| [[0,0],[2,2],[3,10],[5,2],[7,0]] | 20 |
| [[3,12],[-2,5],[-4,1]] | 18 |

### 접근
모든 점 쌍을 "맨해튼 거리가 가중치인 간선"으로 보면, 모든 점을 연결하는 최소 비용은 **최소 신장 트리(MST)의 비용**이다. 모든 점 쌍이 연결 가능한 완전 그래프라서 간선을 따로 만들지 않고 **프림 알고리즘 O(n²)** 로 푼다.

프림은 한 점에서 시작해 트리를 키워 가는 방식이다. 매번 **현재 트리에 가장 싸게 붙일 수 있는 점**을 하나씩 트리에 넣는다.

- `minDist[i]` : 지금 트리에서 점 `i`까지 연결하는 **가장 싼 간선 하나의 비용**. 처음엔 `INT_MAX`, 시작점 0번만 0. 다익스트라의 `dist`처럼 경로 전체의 누적 거리가 아니라, 트리와 `i`를 잇는 간선 하나의 비용이다.
- `visit[i]` : `i`번 점이 트리에 들어왔는지. **트리는 `visit`이 true인 점들의 모임**이며, 반복 횟수 `i`와는 무관하다.

한 번의 반복에서 하는 일:
1. `visit`이 false인 점 중 `minDist`가 **가장 작은 점 `u`** 를 고른다.
2. `u`를 트리에 넣고(`visit[u] = true`), `minDist[u]`를 `answer`에 더한다.
3. 새로 들어온 `u`를 기준으로, 트리 밖의 각 점 `j`에 대해 `u`와 `j`의 거리가 더 싸면 `minDist[j]`를 갱신한다. 이전에 들어온 점들과의 거리는 이미 `minDist[j]`에 반영되어 있으므로 `u`와의 거리만 비교하면 된다.

이 반복을 `n`번 하면 모든 점이 트리에 들어온다. 첫 반복에서는 `minDist[0] = 0`인 0번 점이 비용 0으로 먼저 들어오고, 나머지 `n - 1`번이 실제 간선이다.

> 거리는 미리 계산해 두지 않고 3번 단계에서 필요할 때 바로 구한다. 점 쌍 `(u, j)`의 거리는 `u`가 들어오는 순간 한 번만 계산되므로, `n × n` 표를 미리 만들어도 계산 횟수는 줄지 않고 메모리만 늘어난다. 점 1000개로 재 보니 표를 만드는 시간까지 포함하면 오히려 두 배 가까이 느렸다.

### 자주 하는 실수
- **점을 고르는 조건에서 `&&` 대신 `||`를 쓰면 안 된다.**
  ```cpp
  if (!visit[j] && (u == -1 || minDist[j] < minDist[u])) u = j;   // 올바름
  if (!visit[j] || (u == -1 || minDist[j] < minDist[u])) u = j;   // 틀림
  ```
  `||`면 아직 방문하지 않은 점이기만 하면 무조건 `u`가 바뀌어서, `u`가 "가장 가까운 점"이 아니라 "마지막으로 만난 미방문 점"이 된다. 그러면 첫 반복에서 `minDist`가 `INT_MAX`인 점이 뽑혀 `answer += minDist[u]`가 `int`를 넘치고, `signed integer overflow`로 런타임 에러가 난다.
- 점을 고르는 반복문에서 후보 변수는 안쪽 반복 변수(`j`)여야 한다. 바깥 반복 변수(`i`)를 쓰면 점이 번호 순서(0, 1, 2, ...)로만 뽑히는데, 예제 몇 개는 우연히 맞아서 버그를 놓치기 쉽다. `[[0,0],[10,0],[1,0]]`은 정답이 10이지만 번호 순서로 뽑으면 11이 나온다.
- 점을 고르는 반복문을 1부터 돌리면 0번 점이 후보에서 빠져 마지막 반복에서 `u`가 `-1`인 채로 `visit[u]`에 접근한다. 바깥 반복문을 1부터 돌리면 점을 `n - 1`개만 넣어 마지막 점의 비용이 빠진다.
- 1번 점이 들어온 뒤 4번 점과의 거리가 기존 `minDist[4]`와 **같으면** 갱신되지 않는다. 확인을 안 한 게 아니라 `min(7, 7)`이 그대로 7이라서 값이 안 바뀐 것이다.

### 검산 (points = [[3,12],[-2,5],[-4,1]])
점 사이 거리: 0-1이 12, 0-2가 18, 1-2가 6.

| 반복 | 고른 점 | 더한 비용 | 갱신 후 minDist (0, 1, 2번) |
|------|---------|-----------|------------------------------|
| 시작 | - | 0 | 0, ∞, ∞ |
| 1 | 0번 | 0 | 0, 12, 18 |
| 2 | 1번 | 12 | 0, 12, **6** (1-2가 0-2보다 싸서 갱신) |
| 3 | 2번 | 6 | - |

합계 12 + 6 = 18. 첫 번째 예제는 0, 1, 3, 4, 2번 순서로 들어오고 비용은 4 + 3 + 4 + 9 = 20이다. 3번이 2번보다 먼저 들어오는 데서 트리가 번호 순서로 커지지 않는다는 점을 볼 수 있다.

### 시간복잡도
- 시간: O(n²). 바깥 반복 `n`번, 안쪽에 점 고르기와 `minDist` 갱신이 각각 `n`번. `n ≤ 1000`이라 약 100만 번이다.
- 공간: O(n). 간선을 따로 저장하지 않는다. 크루스칼은 간선 약 50만 개를 만들어 정렬해야 한다.
