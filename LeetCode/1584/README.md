## Min Cost to Connect All Points

- 문제번호: LeetCode 1584
- 난이도: Medium
- 유형: 최소 신장 트리 (MST) / 프림 / 크루스칼 / 유니온 파인드

### 문제
2차원 평면 위 점들의 좌표 배열 `points`가 주어진다 (`points[i] = [xi, yi]`). 두 점 `[xi, yi]`, `[xj, yj]`를 연결하는 비용은 맨해튼 거리 `|xi - xj| + |yi - yj|`이다. 어떤 두 점 사이에도 경로가 **정확히 하나**만 있도록 모든 점을 연결할 때 드는 **최소 비용**을 반환하는 함수를 완성하라.

- 1 ≤ points 길이 ≤ 1000
- -10⁶ ≤ xi, yi ≤ 10⁶
- 모든 점의 좌표 쌍은 서로 다르다

### 입출력 예
| points | 결과 |
|--------|------|
| [[0,0],[2,2],[3,10],[5,2],[7,0]] | 20 |
| [[3,12],[-2,5],[-4,1]] | 18 |

### 핵심 아이디어
모든 점 쌍을 "맨해튼 거리가 가중치인 간선"으로 보면, 모든 점을 연결하는 최소 비용은 **최소 신장 트리(MST)의 비용**이다. 입력에 간선이 따로 주어지지 않고 모든 점 쌍이 연결 가능하므로 간선이 `n(n-1)/2`개인 완전 그래프이다.

> 거리 공식은 문제가 정해 준다. 이 문제의 비용은 피타고라스(직선) 거리가 아니라 가로·세로로만 움직이는 맨해튼 거리이다. 예를 들어 `(0,0)`과 `(3,4)`의 비용은 5가 아니라 7이다. 절댓값을 씌워야 가로·세로 이동 칸 수가 상쇄되지 않고 그대로 더해진다.

MST는 두 가지 방법으로 풀 수 있고, 둘 다 구현했다. 두 방법이 항상 최소를 주는 이유는 **컷 성질**이다. 트리 안의 점과 밖의 점을 가르는 경계를 가로지르는 간선 중 가장 싼 간선은 항상 어떤 MST에 들어간다.

### 접근 1: 프림 O(n²) (`minCostConnectPoints`)
한 점에서 시작해 트리를 키워 가는 방식이다. 매번 **현재 트리에 가장 싸게 붙일 수 있는 점**을 하나씩 트리에 넣는다.

- `minDist[i]` : 지금 트리에서 점 `i`까지 연결하는 **가장 싼 간선 하나의 비용**. 처음엔 `INT_MAX`, 시작점 0번만 0. 다익스트라의 `dist`처럼 경로 전체의 누적 거리가 아니라, 트리와 `i`를 잇는 간선 하나의 비용이다.
- `visit[i]` : `i`번 점이 트리에 들어왔는지. **트리는 `visit`이 true인 점들의 모임**이며, 반복 횟수 `i`와는 무관하다.

한 번의 반복에서 하는 일:
1. `visit`이 false인 점 중 `minDist`가 **가장 작은 점 `u`** 를 고른다.
2. `u`를 트리에 넣고(`visit[u] = true`), `minDist[u]`를 `answer`에 더한다.
3. 새로 들어온 `u`를 기준으로, 트리 밖의 각 점 `j`에 대해 `u`와 `j`의 거리가 더 싸면 `minDist[j]`를 갱신한다. 이전에 들어온 점들과의 거리는 이미 `minDist[j]`에 반영되어 있으므로 `u`와의 거리만 비교하면 된다.

이 반복을 `n`번 하면 모든 점이 트리에 들어온다. 첫 반복에서는 `minDist[0] = 0`인 0번 점이 비용 0으로 먼저 들어오고, 나머지 `n - 1`번이 실제 간선이다.

> 거리는 미리 계산해 두지 않고 3번 단계에서 필요할 때 바로 구한다. 점 쌍 `(u, j)`의 거리는 `u`가 들어오는 순간 한 번만 계산되므로, `n × n` 표를 미리 만들어도 계산 횟수는 줄지 않고 메모리만 늘어난다. 점 1000개로 재 보니 표를 만드는 시간까지 포함하면 오히려 두 배 가까이 느렸다.

### 접근 2: 크루스칼 + 유니온 파인드 O(n² log n) (`kruskal`)
간선을 **싼 것부터** 하나씩 보면서, 사이클이 생기지 않으면 선택하는 방식이다. 거리를 미리 전부 계산해 두는 것이 1단계이다.

1. 모든 점 쌍의 간선 `{거리, i, j}`를 만든다.
2. 거리 오름차순으로 정렬한다. `array<int, 3>`은 앞 원소부터 비교되므로 `{거리, i, j}` 순서로 넣으면 거리 기준으로 정렬된다.
3. 싼 간선부터 보면서 두 점이 **서로 다른 집합**이면 합치고 비용을 더한다. 같은 집합이면 이어도 사이클만 생기므로 건너뛴다.
4. 간선을 `n - 1`개 고르면 멈춘다. 남은 간선은 볼 필요가 없다.

"두 점이 같은 집합인가"를 빠르게 확인하는 것이 **유니온 파인드**이다.

- `parent[i]` : `i`의 부모. 처음엔 점마다 자기 자신이 집합의 대표이므로 `parent[i] = i` (`iota(parent.begin(), parent.end(), 0)`).
- `find(x)` : `x`의 부모를 따라 올라가 **집합의 대표**(`parent[x] == x`인 점)를 찾는다. 두 점의 대표가 같으면 같은 집합이다.
- 경로 압축 : `return parent[x] = find(parent[x])`는 찾은 대표를 `parent[x]`에 바로 저장해서, 다음 `find`가 중간 단계 없이 한 번에 끝나게 한다.
- 합치기 : `parent[ra] = rb`. 두 집합의 **대표끼리** 연결한다.

```cpp
vector<int> parent;
int find(int x) {
    if (parent[x] == x) return x;
    return parent[x] = find(parent[x]);       // 경로 압축
}

int kruskal(vector<vector<int>>& points) {
    int answer = 0, n = points.size();

    vector<array<int, 3>> v;                  // {거리, i, j}
    for (int i = 0; i < n; i++)
        for (int j = i + 1; j < n; j++)
            v.push_back({abs(points[i][0] - points[j][0]) + abs(points[i][1] - points[j][1]), i, j});
    sort(v.begin(), v.end());

    parent.assign(n, 0);                      // 호출마다 초기화
    iota(parent.begin(), parent.end(), 0);

    int cnt = 0;
    for (auto& e : v) {
        int ra = find(e[1]), rb = find(e[2]);
        if (ra != rb) {                       // 서로 다른 집합이면
            parent[ra] = rb;                  // 합치고
            answer += e[0];                   // 비용을 더함
            if (++cnt == n - 1) break;        // 간선 n-1개면 끝
        }
    }
    return answer;
}
```

점이 1개면 간선이 없어 반복문이 돌지 않고 `0`이 나온다.

### 프림 vs 크루스칼
| | 프림 (배열 스캔) | 크루스칼 |
|---|------------------|----------|
| 방식 | 점을 하나씩 트리에 붙임 | 간선을 싼 순서로 사이클 없이 선택 |
| 간선 저장 | 안 함 (필요할 때 거리 계산) | 전부 만들어 정렬 (약 `n²/2`개) |
| 시간 | O(n²) | O(E log E), 여기서는 E ≈ n²/2 |
| 공간 | O(n) | O(E) |

**이 문제(점 1000개, 완전 그래프)** 에서 직접 재 보니 프림 약 4ms, 크루스칼 약 70ms였다. 둘 다 통과하지만 간선이 꽉 찬 그래프에서는 크루스칼이 간선 약 50만 개를 정렬해야 해서 프림이 훨씬 가볍다.

**간선이 적은 그래프(희소 그래프)** 에서는 반대로 크루스칼이 빠르다. 점마다 간선이 3개 정도인 무작위 그래프로 비교했다.

| 점 수 | 간선 수 | 크루스칼 | 프림 (힙) | 프림 (배열 스캔) |
|-------|---------|----------|-----------|------------------|
| 2,000 | 약 6천 | 0.7ms | 1.1ms | 5.5ms |
| 20,000 | 약 6만 | 9.6ms | 14.1ms | 827ms |
| 50,000 | 약 15만 | 25.4ms | 41.0ms | 10,405ms |

배열 스캔 프림은 간선이 적어도 점 고르기가 O(V²)이라 급격히 느려지고, 크루스칼은 있는 간선만 정렬하므로 간선이 적을수록 빨라진다. 우선순위 큐를 쓰는 프림은 O(E log V)로 크루스칼과 비슷하다.

입력 모양이 알고리즘을 고르는 기준이 된다.

| 입력 | 간선 | 잘 맞는 방법 |
|------|------|--------------|
| 간선 목록 (`a b w`) | 입력에 있음 | 크루스칼 |
| 인접 리스트 | 입력에 있음 | 힙을 쓰는 프림 |
| 좌표만 (이 문제) | 입력에 없음, 모든 쌍이 연결 가능 | 배열 스캔 프림 |

### 자주 하는 실수
**프림**
- **점을 고르는 조건에서 `&&` 대신 `||`를 쓰면 안 된다.**
  ```cpp
  if (!visit[j] && (u == -1 || minDist[j] < minDist[u])) u = j;   // 올바름
  if (!visit[j] || (u == -1 || minDist[j] < minDist[u])) u = j;   // 틀림
  ```
  `||`면 아직 방문하지 않은 점이기만 하면 무조건 `u`가 바뀌어서, `u`가 "가장 가까운 점"이 아니라 "마지막으로 만난 미방문 점"이 된다. 그러면 첫 반복에서 `minDist`가 `INT_MAX`인 점이 뽑혀 `answer += minDist[u]`가 `int`를 넘치고, `signed integer overflow`로 런타임 에러가 난다.
- 점을 고르는 반복문에서 후보 변수는 안쪽 반복 변수(`j`)여야 한다. 바깥 반복 변수(`i`)를 쓰면 점이 번호 순서(0, 1, 2, ...)로만 뽑히는데, 예제 몇 개는 우연히 맞아서 버그를 놓치기 쉽다. `[[0,0],[10,0],[1,0]]`은 정답이 10이지만 번호 순서로 뽑으면 11이 나온다.
- 점을 고르는 반복문을 1부터 돌리면 0번 점이 후보에서 빠져 마지막 반복에서 `u`가 `-1`인 채로 `visit[u]`에 접근한다. 바깥 반복문을 1부터 돌리면 점을 `n - 1`개만 넣어 마지막 점의 비용이 빠진다.
- 1번 점이 들어온 뒤 4번 점과의 거리가 기존 `minDist[4]`와 **같으면** 갱신되지 않는다. 확인을 안 한 게 아니라 `min(7, 7)`이 그대로 7이라서 값이 안 바뀐 것이다.

**크루스칼**
- 재귀 람다는 `auto`로 선언할 수 없다. 오른쪽 식 안에 아직 타입이 정해지지 않은 자기 자신(`find`)이 나오기 때문이다. `function<int(int)> find = [&](int x) { ... };`처럼 타입을 적어 주거나, 이 코드처럼 멤버 함수로 만든다.
- 유니온 파인드의 `parent`를 클래스 멤버로 두면 LeetCode가 `Solution` 객체를 재사용할 때 이전 테스트의 값이 남을 수 있다. 함수 시작에서 `parent.assign(n, 0)` 후 `iota`로 매번 초기화하거나 지역 변수로 둔다.
- 간선은 `{거리, i, j}` 순서로 넣어야 한다. 순서를 바꾸면 `sort`가 거리가 아닌 다른 값 기준으로 정렬한다.
- `ra != rb` 확인 없이 합치면 사이클이 생겨 비용이 더 커진다.
- 집합을 합칠 때는 두 점이 아니라 **두 대표**(`find` 결과)를 연결한다. 대표가 아닌 점의 부모를 바꾸면 원래 집합이 쪼개진다.

### 검산
**프림** (points = [[3,12],[-2,5],[-4,1]]). 점 사이 거리: 0-1이 12, 0-2가 18, 1-2가 6.

| 반복 | 고른 점 | 더한 비용 | 갱신 후 minDist (0, 1, 2번) |
|------|---------|-----------|------------------------------|
| 시작 | - | 0 | 0, ∞, ∞ |
| 1 | 0번 | 0 | 0, 12, 18 |
| 2 | 1번 | 12 | 0, 12, **6** (1-2가 0-2보다 싸서 갱신) |
| 3 | 2번 | 6 | - |

합계 12 + 6 = 18. 첫 번째 예제는 0, 1, 3, 4, 2번 순서로 들어오고 비용은 4 + 3 + 4 + 9 = 20이다. 3번이 2번보다 먼저 들어오는 데서 트리가 번호 순서로 커지지 않는다는 점을 볼 수 있다.

**크루스칼** (points = [[0,0],[2,2],[3,10],[5,2],[7,0]]). 간선 10개를 비용순으로 정렬했을 때:

| 순서 | 간선 | 비용 | 판정 | 집합 |
|------|------|------|------|------|
| 1 | 1-3 | 3 | 선택 | {1,3} |
| 2 | 0-1 | 4 | 선택 | {0,1,3} |
| 3 | 3-4 | 4 | 선택 | {0,1,3,4} |
| 4 | 0-3 | 7 | 버림 (같은 집합) | - |
| 5 | 0-4 | 7 | 버림 (같은 집합) | - |
| 6 | 1-4 | 7 | 버림 (같은 집합) | - |
| 7 | 1-2 | 9 | 선택 | {0,1,2,3,4} |

선택한 간선이 `n - 1 = 4`개가 되었으므로 남은 3개는 보지 않고 종료한다. 합계 3 + 4 + 4 + 9 = 20으로 프림과 같다. 선택된 간선 집합도 프림이 만든 트리와 같다.

### 시간복잡도
- 프림: 시간 O(n²), 공간 O(n). 바깥 반복 `n`번, 안쪽에 점 고르기와 `minDist` 갱신이 각각 `n`번. `n ≤ 1000`이라 약 100만 번이다.
- 크루스칼: 시간 O(n² log n), 공간 O(n²). 간선 `n(n-1)/2`개를 만들어 정렬하는 것이 지배적이고, 유니온 파인드의 `find`는 경로 압축 덕분에 사실상 상수 시간이다.
