## Path with Maximum Probability

- 문제번호: LeetCode 1514
- 난이도: Medium
- 유형: 다익스트라 / 최단 경로 / 우선순위 큐

### 문제
`n`개의 노드(0번부터 시작)로 이루어진 **무방향** 가중치 그래프가 간선 목록으로 주어진다. `edges[i] = [a, b]`는 노드 `a`와 `b`를 잇는 간선이고, 그 간선을 건너는 데 성공할 확률이 `succProb[i]`이다. 노드 `start_node`에서 `end_node`까지 가는 경로 중 **성공 확률이 가장 큰 경로**를 찾아 그 확률을 반환하는 함수를 완성하라. 경로가 없으면 `0`을 반환한다. 정답과의 오차가 `1e-5` 이하이면 인정된다.

- 2 ≤ n ≤ 10⁴
- 0 ≤ start_node, end_node < n, start_node ≠ end_node
- 0 ≤ edges 길이 = succProb 길이 ≤ 2 × 10⁴
- 0 ≤ succProb[i] ≤ 1
- 두 노드 사이의 간선은 최대 하나

### 입출력 예
| n | edges | succProb | start | end | 결과 | 설명 |
|---|-------|----------|-------|-----|------|------|
| 3 | [[0,1],[1,2],[0,2]] | [0.5,0.5,0.2] | 0 | 2 | 0.25000 | 0→1→2 = 0.5 × 0.5 = 0.25, 0→2 = 0.2 |
| 3 | [[0,1],[1,2],[0,2]] | [0.5,0.5,0.3] | 0 | 2 | 0.30000 | 0→2 = 0.3이 더 큼 |
| 3 | [[0,1]] | [0.5] | 0 | 2 | 0.00000 | 경로 없음 |

### 접근
**다익스트라 알고리즘**을 "경로 길이의 합이 최소" 대신 "경로 확률의 곱이 최대"로 바꿔서 쓴다. 다익스트라의 기본 구조는 다음과 같다.

```
F := 0;  Y := {v1};
While (the instance is not solved)
    Y 안의 정점만 거쳐서 v1에서 가장 짧게 갈 수 있는 V - Y의 정점 v를 선택;
    v를 Y에 추가;  그 최단 경로의 마지막 간선을 F에 추가;
    if (Y == V) the instance is solved;
```

| 다익스트라 | 이 문제 |
|------------|---------|
| 출발점 `v1` | `start_node` |
| `Y` (경로가 확정된 정점 집합) | 우선순위 큐에서 꺼내 처리한 정점들 |
| 경로 길이 = 간선 길이의 **합** | 경로 확률 = 간선 확률의 **곱** |
| 가장 **짧은** 경로의 정점을 선택 | 확률이 가장 **큰** 정점을 선택 |

- `prob[i]` : `start_node`에서 `i`까지 가는 **최대 확률**. `prob[start_node] = 1`, 나머지는 0으로 시작한다.
- 인접 리스트는 무방향이라 `a→b`, `b→a`를 **둘 다** 넣는다.
- 우선순위 큐는 `priority_queue<pair<double, int>>`로 **최대 힙**이다. `pair`는 앞 원소부터 비교하므로 `{확률, 정점}` 순서로 넣어야 확률이 큰 정점부터 나온다.

한 번의 반복에서 하는 일:
1. 힙에서 확률이 가장 큰 정점 `u`를 꺼낸다.
2. `u`가 `end_node`면 그 확률이 곧 최대 확률이므로 바로 반환한다.
3. 이미 더 좋은 확률로 처리된 낡은 항목이면(`p < prob[u]`) 건너뛴다.
4. `u`의 이웃 `v`에 대해 `np = p × (u-v 간선 확률)`이 `prob[v]`보다 크면 `prob[v]`를 갱신하고 `{np, v}`를 힙에 넣는다.

힙이 비도록 도착점이 나오지 않으면 도달할 수 없으므로 `0`을 반환한다.

```cpp
vector<vector<pair<int, double>>> adj(n);
for (int i = 0; i < (int)edges.size(); i++) {
    int a = edges[i][0], b = edges[i][1];
    adj[a].push_back({b, succProb[i]});
    adj[b].push_back({a, succProb[i]});
}
vector<double> prob(n, 0.0);
prob[start_node] = 1.0;
priority_queue<pair<double, int>> pq;
pq.push({1.0, start_node});

while (!pq.empty()) {
    auto [p, u] = pq.top();
    pq.pop();
    if (u == end_node) return p;
    if (p < prob[u]) continue;
    for (auto& [v, w] : adj[u]) {
        double np = p * w;
        if (np > prob[v]) { prob[v] = np; pq.push({np, v}); }
    }
}
return 0.0;
```

### 왜 최적인가 (확률이 1 이하여야 하는 이유)
"그때그때 가장 큰 값을 확정하면 나중에 더 좋은 경로가 생기지 않나?"라는 의문이 생길 수 있다. 두 경우를 나눠서 봐야 한다.

- **아직 꺼내지 않은 정점의 값이 나중에 올라오는 경우는 처리된다.** 예제 1에서 2번 정점은 직행 경로로 처음엔 0.2이다가, 1번을 꺼낸 뒤 `0.5 × 0.5 = 0.25`로 갱신된다. 낡은 항목 `{0.2, 2}`는 `p < prob[u]`에서 걸러진다.
- **이미 꺼낸(확정한) 정점의 값이 나중에 올라오는 경우는 생기지 않는다.** 꺼낸 정점 `u`의 확률 `p`는 힙에 있는 값 중 최대이고, `u`로 가는 다른 경로는 아직 확정되지 않은 정점 `x`(확률 ≤ `p`)를 거쳐야 하며, 이후 0~1을 곱하면 작아지기만 하므로 `p`를 넘을 수 없다.

그래서 간선 확률이 **1 이하**라는 조건이 다익스트라의 "음수 간선 없음"과 같은 역할을 한다. 확률이 1보다 큰 간선이 있으면 깨진다. 방향 있는 간선 `0→1 (0.5)`, `0→2 (0.4)`, `2→1 (3.0)`에서 다익스트라는 1번을 먼저 `0.5`로 확정하지만 실제 최대는 `0.4 × 3.0 = 1.2`이다.

### 자주 하는 실수
- 큰 값을 찾으려고 반복문을 한 겹 더 쓰면 O(n³)이 되는 것이 아니다. 의사코드처럼 배열을 훑어 가장 큰 값을 찾는 방식도 바깥 반복 `n`번 × 훑기 `n` = O(n²)이다. n³은 모든 정점 쌍의 경로를 구하는 플로이드 같은 경우이다. `n ≤ 10⁴`에서 O(n²)은 약 10⁸번이라 아슬아슬하고, 우선순위 큐를 쓰면 O(E log V)로 약 30만 번이면 끝난다.
- 힙에 넣을 때 `{정점, 확률}` 순서로 넣으면 정점 번호가 큰 것부터 나온다. 최대 힙의 정렬 기준은 `pair`의 앞 원소이므로 `{확률, 정점}`이어야 한다.
- 무방향 그래프인데 간선을 한쪽 방향으로만 인접 리스트에 넣으면 도착 못 하는 경우가 생긴다.
- 힙에는 같은 정점이 여러 번 들어갈 수 있다. 꺼낼 때 이미 확정된 낡은 항목을 `p < prob[u]`로 걸러야 한다.
- 확률을 곱하다 보면 값이 매우 작아져 0으로 언더플로할 수 있지만, 오차 허용이 `1e-5`이므로 결과가 0에 가까운 경우 `0`을 반환해도 인정된다.

### 검산 (n = 3, edges = [[0,1],[1,2],[0,2]], succProb = [0.5,0.5,0.2], start = 0, end = 2)
| 단계 | prob (0, 1, 2번) | 일어난 일 |
|------|------------------|-----------|
| 시작 | 1, 0, 0 | 0번을 힙에 넣음 |
| 0번을 꺼냄 | 1, 0.5, 0.2 | 이웃 갱신. 2번은 직행 경로로 0.2 |
| 1번을 꺼냄 (0.5) | 1, 0.5, **0.25** | 2번이 `0.5 × 0.5 = 0.25`로 올라옴 |
| 2번을 꺼냄 (0.25) | - | 도착점이므로 `0.25` 반환 |

두 번째 예제는 `0→2`가 0.3이고 `0→1→2`가 0.25이므로 직행이 더 커서 `0.3`이 나온다. 세 번째 예제는 2번에 도달할 수 없어서 힙이 비고 `0`이 나온다.

### 시간복잡도
- 시간: O(E log V). 간선 하나를 볼 때 힙에 넣고 꺼내는 비용이 log. 최대 크기(노드 10⁴개, 간선 2 × 10⁴개)에서 약 5ms였다.
- 공간: O(V + E). 인접 리스트와 `prob` 배열, 힙.
