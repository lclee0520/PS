## 입국심사

- 문제번호: 43238
- 난이도: Level 3
- 유형: 이분탐색 (parametric search)

### 문제
n명이 입국심사를 위해 줄을 서서 기다린다. 각 심사관마다 한 명을 심사하는 데 걸리는 시간이 다르다. 모든 사람이 심사를 받는 데 걸리는 시간을 최소로 하고 싶다. 대기 인원 n과 각 심사관의 심사 시간 배열 `times`가 주어질 때, 모든 사람이 심사를 받는 데 걸리는 시간의 **최솟값**을 반환하는 함수를 완성하라.

- 1 ≤ n ≤ 1,000,000,000
- 1 ≤ times의 원소 ≤ 1,000,000,000
- 1 ≤ times의 길이 ≤ 100,000

### 입출력 예
| n | times | return |
|---|-------|--------|
| 6 | [7, 10] | 28 |

### 이분탐색으로 접근하는 이유
"최소 시간이 정확히 얼마인가"를 직접 구하긴 어렵지만, **"시간 t 안에 n명을 모두 심사할 수 있는가?"** 는 쉽게 판정할 수 있다.

- 시간 t가 주어지면, 심사관 i는 `t / times[i]` 명을 심사할 수 있다.
- 모든 심사관의 처리 인원을 더한 `num`이 `n` 이상이면, t는 "충분한 시간".
- 이 판정 함수는 t가 커질수록 결과가 `false → true`로 단조 증가(한 번 충분해지면 계속 충분함) 하므로, **가장 작은 "충분한" t**를 이분탐색으로 찾을 수 있다 (parametric search).

### 접근
1. 하한 `low = 1`, 상한 `high = n * min(times)`.
   - 가장 빠른 심사관 한 명만 써도 n명을 끝낼 수 있는 시간이므로 항상 충분한 상한이 된다.
2. `mid = (low + high) / 2` 에 대해 판정 함수 `num = Σ(mid / times[i])` 를 계산한다.
3. `num >= n` (충분함) → 정답 후보로 `mid`를 저장하고, 더 작은 값도 가능한지 `high = mid - 1`로 탐색 범위를 줄인다.
4. `num < n` (부족함) → `low = mid + 1`로 더 큰 값을 탐색한다.
5. `low > high`가 되면 종료, 마지막으로 저장된 후보가 답.

> 주의: 조건을 `num == n`(정확히 일치)으로 잡으면 안 된다. 여러 심사관의 처리량이 동시에 겹치는 순간 `num`이 `n`을 건너뛰고 넘어갈 수 있어 (예: `times = [2, 2]`일 때 `num`은 항상 짝수) 홀수 `n`에선 영원히 `num == n`이 안 나와 무한루프에 빠진다. 반드시 `num >= n` 으로 판정해야 한다.

### 검산 (n = 6, times = [7, 10])
- t=27: 27/7=3, 27/10=2 → 5명, 부족
- t=28: 28/7=4, 28/10=2 → 6명, 충분 → 후보
- t=27 이하로는 부족하므로 최종 답은 `28`

### 시간복잡도
O(len(times) × log(n × min(times))) — 이분탐색 각 단계마다 심사관 수만큼 순회
