## 최적의 행렬 곱셈

- 문제번호: 12942
- 난이도: Level 3
- 유형: DP (구간 DP, 연쇄 행렬 곱셈)

### 문제
크기가 `a×b`인 행렬과 `b×c`인 행렬을 곱하면 `a×b×c`번의 곱셈 연산이 필요하다. 행렬 곱셈은 결합법칙이 성립하므로 어떤 순서로 곱해도 결과는 같지만, **곱하는 순서에 따라 필요한 곱셈 연산 횟수가 달라진다.**

각 행렬의 크기가 담긴 2차원 배열 `matrix_sizes`가 주어질 때, 모든 행렬을 곱하기 위한 **최소 곱셈 연산 횟수**를 반환하라.

- 행렬 개수: 3 이상 200 이하
- 각 행렬의 행, 열 크기: 200 이하 자연수
- 주어진 순서대로 곱할 수 있는 행렬만 입력으로 주어진다 (앞 행렬의 열 = 뒤 행렬의 행)

### 입출력 예
| matrix_sizes | result |
|--------------|--------|
| `[[5, 3], [3, 10], [10, 6]]` | 270 |

- `(A×B)×C` = 5×3×10 + 5×10×6 = 150 + 300 = 450
- `A×(B×C)` = 3×10×6 + 5×3×6 = 180 + 90 = **270**

### 접근

#### 1. DP 정의
- `v[i][j]`: `i`번 ~ `j`번 행렬을 모두 곱하는 데 필요한 **최소 곱셈 횟수**
- `v[i][i] = 0` (행렬 하나는 곱할 필요 없음)
- 나머지 칸은 `INT_MAX`로 시작해서 최솟값으로 갱신
- 정답: `v[0][n-1]`

#### 2. 점화식
구간 `[i, j]`를 **마지막으로 곱하는 위치 `k`** (`i ≤ k < j`) 기준으로 왼쪽 `[i, k]`와 오른쪽 `[k+1, j]`로 나눈다.

```
v[i][j] = min( v[i][k] + v[k+1][j] + (두 결과 행렬을 곱하는 비용) )
```

두 결과 행렬의 크기:
- 왼쪽 `i`~`k`를 곱한 결과 = **`i`의 행 × `k`의 열**
- 오른쪽 `k+1`~`j`를 곱한 결과 = **`k+1`의 행(= `k`의 열) × `j`의 열**

```
두 결과를 곱하는 비용 = matrix_sizes[i][0] * matrix_sizes[k][1] * matrix_sizes[j][1]
```

#### 3. 채우는 순서
`v[i][j]`를 계산하려면 `v[i][k]`(같은 행)와 `v[k+1][j]`(아래 행)가 먼저 채워져 있어야 한다.
→ `i`를 **뒤에서부터** (`n-1 → 0`) 돌린다. (1843 사칙연산과 같은 구조)

#### 4. 곱하는 순서 복원
최솟값이 갱신될 때의 `k`를 `pos[i][j]`에 저장해 두면, 재귀로 괄호를 복원할 수 있다.

```cpp
string order(vector<vector<int>>& pos, int i, int j){
    if(i == j) return string(1, 'A' + i);
    int k = pos[i][j];
    return "(" + order(pos, i, k) + " x " + order(pos, k + 1, j) + ")";
}
```

예제 결과: `(A x (B x C))`

### 검산 (예제)
`A(5×3)`, `B(3×10)`, `C(10×6)`

| 구간 | 나누는 방법 | 비용 | v | pos |
|------|-------------|------|---|-----|
| [0,1] | A \| B | 5×3×10 = 150 | 150 | 0 |
| [1,2] | B \| C | 3×10×6 = 180 | 180 | 1 |
| [0,2] | k=0: A \| (B×C) → 0 + 180 + 5×3×6 = **270**<br>k=1: (A×B) \| C → 150 + 0 + 5×10×6 = 450 | | **270** | **0** |

### 교재 알고리즘(minmult)과 비교
교재의 연쇄 행렬 곱셈 알고리즘:

```
for(i=1; i <= n; i++) M[i][i] = 0;
for(diagonal = 1; diagonal <= n-1; diagonal++)
    for(i=1; i <= n-diagonal; i++) {
        j = i + diagonal;
        M[i][j] = minimum(M[i][k] + M[k+1][j] + d[i-1]*d[k]*d[j]);   // i <= k <= j-1
        P[i][j] = 최소치를 주는 k의 값
    }
return M[1][n];
```

점화식과 아이디어는 **완전히 같고**, 구현 방식만 다르다.

| | 교재 (minmult) | 내 풀이 |
|---|---|---|
| 인덱스 | 1부터 (`M[1][n]`) | 0부터 (`v[0][n-1]`) |
| 행렬 크기 표현 | 1차원 `d[0..n]`: `i`번 행렬 = `d[i-1] × d[i]` | 2차원 `matrix_sizes[i] = {행, 열}` |
| 곱셈 비용 | `d[i-1] * d[k] * d[j]` | `ms[i][0] * ms[k][1] * ms[j][1]` |
| 채우는 순서 | **대각선(구간 길이)** 1 → n-1 순서 | **행 `i`를 역순**으로 (`n-1 → 0`) |
| `j` 범위 | `j = i + diagonal` → 항상 `j > i`인 칸만 | `j`를 `0`부터 돌리고 `k < j` 조건으로 `j ≤ i`는 건너뜀 |
| 최솟값 | `minimum(...)`으로 표현 | `INT_MAX`로 초기화 후 `if`로 비교·갱신 |
| 순서 복원 | `P[i][j]` | `pos[i][j]` (같은 역할) |

- **비용식 대응**: `d[i-1]` = `i`번 행렬의 행, `d[k]` = `k`번 행렬의 열, `d[j]` = `j`번 행렬의 열. 0-based로 옮기면 그대로 `ms[i][0]`, `ms[k][1]`, `ms[j][1]`이다.
- **채우는 순서**: 교재는 구간 길이가 짧은 것부터(대각선 방향), 내 풀이는 아래 행부터 채운다. 방향은 다르지만 둘 다 `M[i][k]`, `M[k+1][j]`가 항상 먼저 계산되므로 결과가 같다.

### 풀면서 막혔던 부분
- `matrix_sizes()`처럼 vector를 함수처럼 호출 → `.size()`
- `vector<vector<int>> v(개수, 값)` 인자 순서를 반대로 씀
- `v[i][j] == INT_MAX;` (비교) → `=` (대입). 모든 칸이 0으로 남아 답이 0이 됨
- `k`를 맨 바깥에 둔 플로이드-워셜 구조 → `k`가 `num-1`일 때 `v[k+1]` 범위 초과로 실행 중 에러
- `i`를 앞에서부터 돌림 → 아래 행 `v[k+1][j]`가 아직 `INT_MAX`인 상태로 더해져 overflow, 음수(`-2147483560`)가 최솟값으로 뽑힘

### 시간복잡도
O(N³) — 구간 `[i, j]` O(N²)개 × 분할 지점 `k` O(N). N ≤ 200이라 약 1.3×10⁶번 연산.

값 범위: 문제에서 답이 2³¹ - 1 이하로 보장되어 `int`로 충분하다.
